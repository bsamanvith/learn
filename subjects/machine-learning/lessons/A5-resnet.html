Assignment A5 · after lessons 15–16

A residual network in NumPy

Build a small ResNet from its parts: convolution by unfolding windows into a matrix (im2col) and its adjoint for the backward pass, max pooling, batch normalisation with running statistics, residual blocks with projection shortcuts, and data augmentation by random shifts. Then train it on MNIST to better than 99% test accuracy, and run experiments that test the lessons' claims: that residual connections make depth trainable, that batch norm behaves differently in training and evaluation, and that convolutions make a network robust to translation where an MLP is not. An autograder checks every part. Expect eight to ten hours.

Set-up

You need Python 3 and NumPy. From the repository root:

cd subjects/machine-learning/assignments/A5-resnet
cp starter.py mine.py          # work in your own copy
python3 check.py mine.py       # run as often as you like

The checker compares your forward passes with loops written straight from the definitions, and every backward pass with central finite differences, on small arrays of awkward shapes, strides and paddings. It checks that col2im is exactly the adjoint of im2col, that your convolution is translation equivariant, and that batch norm's running statistics and evaluation mode follow the usual conventions. The last check trains a small ResNet end to end to recognise shapes anywhere in an image. It takes about ten seconds in total. Floating-point warnings are errors.

The design

Unlike A4, there is no automatic differentiation here: every layer has a forward(x) that caches what it needs, and a backward(g) that receives the gradient of the loss with respect to its output, stores the gradients of its parameters in layer.grads, and returns the gradient with respect to its input. Linear and ReLU are written for you as examples, and so are the Sequential container, the resnet constructor and the MNIST loader. This is how deep-learning libraries were written before autograd, and it is how the fused kernels inside today's libraries still work.

Convolution as a matrix product

A convolution with $F$ filters of shape $C\times k\times k$ computes, at each output position, the dot product of each filter with one $C\times k\times k$ window of the input. Lay every window out as a row of a matrix: for a batch of $N$ inputs and an output of size $O_H\times O_W$, the matrix cols has $NO_HO_W$ rows and $Ck^2$ columns. Then the whole convolution is one matrix product with the filters laid out as rows of a $F\times Ck^2$ matrix:

$$\text{out} = \text{cols}\cdot W_\text{mat}^\top + \mathbf{b}, \qquad (NO_HO_W\times Ck^2)\cdot(Ck^2\times F).$$

Matrix products are what numerical libraries do fastest, which makes this the standard way to implement convolution on CPUs (and, with variations, on GPUs). It costs memory: each input pixel is copied into up to $k^2$ rows. The backward pass follows from lesson 13's rule for a matrix product. With $G$ the output gradient laid out as $NO_HO_W\times F$ rows, $\bar W_\text{mat} = G^\top\text{cols}$ and $\overline{\text{cols}} = GW_\text{mat}$. Each entry of cols is a copy of some input pixel, so the gradient of a pixel is the sum of the gradients of all its copies. Scattering them back and adding is col2im, which is the adjoint (the transpose) of the linear map im2col:

$$\langle\operatorname{im2col}(x), Y\rangle = \langle x, \operatorname{col2im}(Y)\rangle \quad\text{for all } x, Y .$$

The checker tests exactly this identity. (It is the general principle: the backward pass of any linear map is its transpose, which is also why the backward pass of a convolution is a convolution, as in problem set P5, problem 3.)

The network resnet() is a $3\times3$ convolution with 16 channels, batch norm, ReLU and $2\times2$ max pooling (28 to 14 pixels), then three residual blocks with 16, 32 and 64 channels, the second and third with stride 2 (14 to 7 to 4), then global average pooling and a linear layer: 77,754 parameters, an eighth as many as A4's 670,000-parameter MLP.

Experiments and write-up

Once all fifteen checks pass, write a training script that uses your library. Hold out the last 10,000 training images for validation and make every choice on them; touch the test set once, at the end. Write a short paragraph and include a plot or a table for each experiment.

  1. The baseline. Train resnet() for 3 epochs with batch size 128, SGD with momentum 0.9, weight decay $5\times10^{-4}$, a learning rate of 0.2 with cosine decay to 0, and random shifts of up to 2 pixels. Plot the training loss and the validation accuracy. Our solution reaches 99.2% validation and 99.24% test accuracy, at about three and a half minutes per epoch on one CPU core. Then repeat with learning rates 0.1 and 0.02 (our solution: 98.9% and 96.6% test). Why is a network with batch norm this sensitive to a small learning rate? Look at the training loss in the first 200 steps, and at what the blocks compute at initialisation.
  2. Translation. Shift every test image by $s = 0, 1, \dots, 6$ pixels to the right (filling with zeros), and plot test accuracy against $s$ for your ResNet and for A4's MLP (or any MLP you train). Repeat for your ResNet trained without augmentation. Explain each curve with lesson 15: which part of the network is equivariant, which part makes it invariant, and why is the invariance only approximate?
  3. Depth, with and without shortcuts. Add an option to ResidualBlock that drops the shortcut (a "plain" block). Build networks with 1, 3 and 6 blocks per stage, plain and residual, and train each for one epoch. Plot final training loss against depth. Which gets worse with depth? Relate it to lesson 16's degradation experiment and to P5, problem 6. Then set bn2's initial $\gamma$ to 1 instead of 0 in the deepest residual network: does it matter?
  4. Batch norm's two modes. Evaluate your trained network on the test set in training mode (batch statistics) with batch sizes 500, 32, 4 and 1, and in evaluation mode. Explain the numbers. Then train for one epoch at a constant learning rate of 0.05 and evaluate in evaluation mode, and again after recomputing the running statistics exactly from 10,000 training images: we saw 84.5% before and 95.0% after. Why are the running averages wrong, and why does this go away with a decaying learning rate? Then train a network with no batch norm at all: remove the layers, and to keep each residual branch small at the start, multiply it by a learned scalar that starts at 0 (the idea of ReZero and Fixup). Compare how large a learning rate each version tolerates before training diverges.
  5. Look inside. Show the 16 stem filters as $3\times3$ images, and the 16 feature maps they produce for one test digit. Compute the receptive field of a unit in the last block (count the stem, the pooling, and each convolution with its stride). Is it larger than the image? Find the 20 test images your network gets wrong: are they the same kind of mistake as in A4?
