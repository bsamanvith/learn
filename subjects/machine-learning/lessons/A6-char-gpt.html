Assignment A6 · after lessons 19, 20 and 26

A character-level GPT

Build a GPT from scratch in NumPy, every forward and backward pass by hand: layer normalisation, GELU, multi-head causal self-attention, pre-norm residual blocks, and the full model. Then add what turns a network into a working language model: batching, a warm-up and cosine learning-rate schedule, gradient clipping, AdamW with weight decay applied only where it belongs, and generation with a KV cache, temperature and top-$k$. Train it on Shakespeare, compare it with the n-gram and MLP models of lessons 26 and 27, and take it apart with ablations. An autograder checks every part. Expect eight to ten hours, plus training time.

Set-up

You need Python 3 and NumPy. From the repository root:

cd subjects/machine-learning/assignments/A6-char-gpt
cp starter.py mine.py          # work in your own copy
python3 check.py mine.py       # run as often as you like (about 10 seconds)

Lesson 20's code contains a GPT, and you may read it, but the starter is organised differently (parameters live in dictionaries, attention has a cached single-step path, the feed-forward layer uses GELU) and the checker tests each piece on its own. Passing means the following, in order of the parts. Every gradient matches central finite differences in float64. Attention matches a slow loop over heads and positions, and changing a later token never changes an earlier output. The cached single-step path gives exactly the logits of the full forward pass. The optimiser matches a reference implementation over several steps. Greedy generation matches the argmax of repeated full forward passes, and sampled tokens follow the tempered softmax. A small model learns a repeating text.

Conventions

Activations have shape $(B, T, d)$. Each layer keeps its parameters in self.params, a dictionary, and its backward pass stores the matching gradients in self.grads and returns the gradient with respect to its input. Linear and Embedding are given as worked examples. The model computes in float32 for speed; the checker converts it to float64.

Two details matter more than they look. Weight decay is applied to weight matrices and embeddings but not to biases or layer-norm gains: decaying a gain towards zero fights the normalisation it is there to undo. And the output projections of attention and of the feed-forward layer, which add into the residual stream, are initialised with standard deviation $0.02/\sqrt{2n_\text{layer}}$ as in GPT-2, so that the residual stream's variance does not grow with depth at initialisation; the constructor already does this.

Experiments and write-up

Once all seventeen checks pass, write a training script. Use the first 90% of Tiny Shakespeare (load_shakespeare() downloads it) for training and the rest for validation, and evaluate the validation loss on a fixed set of 200 windows. Write a short paragraph and include a plot or a table for each experiment.

  1. The baseline. Train GPT(65, 64, d=64, heads=4, n_layer=4) with batches of 32 windows of 64 characters for 3,000 steps, with AdamW (weight decay 0.1, $\beta_2 = 0.95$), learning rate warming up over 200 steps to $3\times10^{-3}$ and decaying to $3\times10^{-4}$, and gradients clipped at norm 1. Plot the training and validation loss. @@A6_BASE@@ Convert the final loss to bits per character, and compare it with the 8-gram model of lesson 26 trained on the same text (fit one) and with lesson 27's best MLP, 1.816 nats. Generate 200 characters at temperatures 0.5, 0.8 and 1.0 from the prompt "ROMEO:" and describe the differences.
  2. Ablations. Retrain three variants with everything else fixed: no position embeddings (set them to zero and skip their update), a single layer, and a context of 16 characters. Report the validation losses in a table. Which matters most, and why? What does a model without position embeddings know about word order? (Think about which functions of a set of tokens a causal mask still lets attention compute.)
  3. What the heads do. Plot the attention weights of every head in the first layer on one line of text, as $T\times T$ heat maps. Find at least two heads with an interpretable pattern, for instance one that attends to the previous character, or one that attends to the most recent space or newline, and test your description on other lines.
  4. The KV cache. Time the generation of 60 characters with generate, and with a version that calls model.forward on the whole sequence for every new token. Explain the ratio with the operation counts of lesson 29. How would it change with a context of 1,024?
  5. A small scaling study. Train models with $d = 32$, 64 and 128 (4 layers, everything else as in the baseline, and the learning rate lowered for the largest if it is unstable) and plot the final validation loss against the number of non-embedding parameters on log–log axes. Is it consistent with lesson 27's power laws? What would you need to change to measure a compute-optimal frontier?

Grading yourself

Seventeen checker passes are worth 50%. Each experiment is worth 10%: full marks if the plot or table is right and the explanation names the mechanism. A stretch goal: replace the character vocabulary with your own byte-level BPE tokeniser of 512 tokens (lesson 26 and problem set P7), retrain, and compare the models in bits per character, not per token.
